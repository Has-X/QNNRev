# Recompiling ONNX to QNN / QAIRT HTP Context Binaries

`qnnrev compile` supports both ONNX Runtime QNN Execution Provider compilation
(QAIRT 2.26 / 2.39) and the standalone QAIRT SDK pipeline (QAIRT 2.44 / 2.52).

## QAIRT 2.44 and 2.52 Standalone Pipeline

The standalone pipeline runs three steps generated by `qnnrev. __main__.build_qairt_plan`:

1. `qairt-converter`: Converts ONNX (`-d name=dims`, optional `--quantization_overrides`) to an FP32 `.dlc`.
2. `qti.aisw.converters.common.dlc_quantizer.DLCQuantizer`: Calibrates W8A16 quantization (`act_bitwidth=16`, `weights_bitwidth=8`, `bias_bitwidth=32`, per-channel & per-row quantization with quantized bias).
3. `qnn-context-binary-generator`: Compiles the quantized DLC against `libQnnHtp.so` with `libQnnHtpNetRunExtensions.so` using `htp_out.json` -> `htp_in.json`.

### Critical Configuration Rules

1. **DLC stem must match `graph_name`**: Keep the intermediate FP32 DLC filename stem identical to `graph_names[0]` in `htp_in.json` (`<graph_name>.dlc`). If the stem differs, `qnn-context-binary-generator` fails to match the per-graph entry in `htp_in.json` and silently falls back to `O=2` / `vtcm_mb=4`.
2. **Asymmetric parameter quantization for HTP**: `DLCQuantizer` must retain asymmetric parameter schema with `use_per_channel_quantization=True`, `use_per_row_quantization=True`, and `enable_per_row_quantized_bias=True` for HTP `LayerNorm` / `FullyConnected` compatibility.
3. **QAIRT 2.52 HTP options**: Selecting `--qairt-version 2.52` or `--htp-opt-252` emits:
   - `dlbc: 1`, `dlbc_weights: 1`
   - `vtcm_retention: 1`, `cached_weights: 1`
   - `weights_packing: true`, `precision_compensation: true`
   - `advanced_activation_fusion: true`, `high_precision_sigmoid: true`

### Dry-Run Inspection

Always inspect generated paths, JSON configs, and exact command arrays first with `--dry-run`:

```bash
qnnrev compile \
  --onnx model.onnx \
  --out-dir out_252/ \
  --qairt-version 2.52 \
  --graph-name bert_model \
  --input-dim input_ids=1,128 \
  --input-list calib_inputs.txt \
  --soc-model 61 \
  --dsp-arch v73 \
  --vtcm-mb 2 \
  --opt-level 3 \
  --dry-run
```

## QAIRT 2.26 / 2.39 via ONNX Runtime QNN EP

For QAIRT 2.26 / 2.39, `qnnrev compile --qairt-version 2.26` or `2.39` delegates to
`python -m qnnrev.export.ort_qnn`, which loads `onnxruntime-qnn`, sets
`ep.context_enable=1` and `dump_qnn_ir_dlc=1`, compares outputs against
`CPUExecutionProvider`, and emits `context.bin`, IR DLCs, and `compile-receipt.json`.
On `aarch64` hosts when using CPU backend fallback, `ORT_QNN_ENABLE_CPU_BACKEND=1`
is set automatically.

## Parity Verification

Compare unsigned 16-bit QNN raw outputs (`--a-dtype u16 --a-scale ... --a-offset ...`)
or FP32 dumps against reference FP32 outputs (`.npz` or `*.raw` directories) using:

```bash
qnnrev verify \
  --a htp_outputs/ --a-dtype u16 --a-scale 0.000512 --a-offset -32768 \
  --b ref_outputs/ --b-dtype f32 \
  --min-raw-cos 0.98 --min-dev-cos 0.98 \
  --htp-executed
```

`qnnrev verify` checks both per-probe raw cosine similarity and cross-probe
deviational cosine similarity (mean-subtracted across probes when multiple probes
are supplied) to catch collapsed or bias-only constant outputs.
